# Dataset Selection

## Dataset Source
* **Source:** GitHub Repository (Neeraj08823/Sugar_cosmetics_Instagram_Analytics)
* **Dataset Name:** Sugar Cosmetics Instagram Analytics Data
* **URL/Source Reference:** [sugar_cosmetics_instagram_data.xlsx](https://raw.githubusercontent.com/Neeraj08823/Sugar_cosmetics_Instagram_Analytics/main/Data/sugar_cosmetics_instagram_data.xlsx)

## Dataset Dimensions
* **Number of Rows:** 50,000
* **Number of Columns:** 14

## Feature Descriptions
* `Post Date`: The date the content was posted.
* `Post Type`: Type of content (Image, Video, Carousel, Story).
* `Campaign Type`: The marketing campaign category (Giveaway, Tutorial, etc.).
* `Hashtags`: Hashtags used in the post.
* `Audience Emotion`: Sentiment indicator of the audience.
* `Engagement Source`: Where the engagement originated (Home, Explore, etc.).
* `Impressions`: Total views on the post.
* `Reach`: Number of unique accounts that saw the post.
* `Likes`: Total likes.
* `Comments`: Total comments.
* `Shares`: Total shares.
* `Saves`: Total saves.
* `Profile Visits`: Profile visits generated by the post.
* `Follows`: Follows generated by the post.

## Target Variable
* **Target:** `Reach` (The number of unique users who saw the post)

## Why it was selected
This dataset was chosen because it is a publicly available, robust dataset (50,000 rows) containing real-world Instagram performance metrics. Crucially, it includes the explicit `Reach` metric, various content categorizations (`Post Type`, `Campaign Type`), and all major engagement metrics (`Likes`, `Comments`, `Shares`, `Saves`), making it ideal for predictive modeling and engagement rate calculations.

## Limitations
* **Lack of Hourly Timestamp:** The dataset only provides `Post Date` (YYYY-MM-DD), not the exact time of day (Hour:Minute). 
* **Adaptation Made:** Following the project guidelines ("If the selected dataset does not contain a feature mentioned in the concept... Adapt the analysis/model accordingly"), the analysis and recommendation engine will focus on recommending the optimal **Posting Day** (e.g., Monday vs. Friday) rather than the exact Posting Time (e.g., 8 PM). This correctly utilizes the available data without fabricating timestamps.
* **No Caption Text:** The dataset provides `Hashtags` but no raw `Caption` text. Word count and caption length analysis will be omitted or replaced with hashtag count analysis.
* **No Direct Audience Activity Insights:** Audience activity will be inferred from historical reach and engagement by day.

## Potential Leakage
Features like `Likes`, `Comments`, `Shares`, `Saves`, `Impressions`, `Profile Visits`, and `Follows` occur *after* publication. To prevent data leakage, these variables **must not** be used as input features to predict `Reach` for new posts. They will be strictly reserved for EDA and calculating the custom engagement metric.

## Data-quality Observations
* The dataset is well-structured and large enough to train robust models without overfitting.
* Temporal data needs to be parsed from the `Post Date` column to create `day_of_week`, `is_weekend`, and `month` features.
